# Задание Codex: доработка chess-trainer после ревью

Репозиторий уже собран тобой и лежит в `~/projects/chess-trainer`, задеплоен на
https://yyalkov-ship-it.github.io/chess-trainer/. Ничего не переписывай с нуля и не меняй стек:
Vite + TypeScript + React, chessground, chess.js, stockfish 18 lite single-threaded, vite-plugin-pwa,
localStorage, деплой в GitHub Pages. Правь существующие файлы.

Полный разбор проблем — в `REVIEW.md` в корне репозитория, прочитай его первым делом.

## Главное правило этой задачи

Приложение учит десятилетнего ребёнка. Любое утверждение о шахматах, которое попадает в JSON
(опровержение, ответ соперника, оценка «это ошибка»), должно быть **посчитано движком, а не
придумано**. В прошлой версии ответы соперника были выдуманы: заглушка `Bb7` стояла в пяти
опровержениях из шестнадцати. Так больше нельзя.

Поэтому первым шагом сделай инструмент проверки, а контент правь уже с его помощью.

## 0. Скрипт проверки движком (делать первым)

Создай `scripts/verify-with-engine.ts` — запускается в Node (`npm run verify:engine`), поднимает
пакет `stockfish` как обычный Node-модуль (не браузерный воркер), анализирует на глубине 20 и печатает
отчёт. Он должен проверять для каждой партии:

1. `answerSan` каждого момента совпадает с настоящим ходом партии на этом `ply` (сравнивать после
   `rstrip('+#')`, но суффикс шаха тоже валидировать отдельно — см. пункт 7).
2. Для каждого опровержения: цена ошибки = оценка после `answerSan` минус оценка после ошибочного
   хода, обе приведённые к POV стороны, которая ходит. Печатать цену в пешках.
3. Для каждого опровержения: первый ход поля `line` совпадает с первым ходом главного варианта
   движка после ошибочного хода.
4. Для каждого упражнения: `answerSan` — первый выбор движка, отрыв от второго ≥150 сотых, и FEN
   упражнения не встречается ни в одной позиции разбираемой партии.

Скрипт должен завершаться ненулевым кодом при нарушении. Добавь его в CI после `validate:content`.

## 1. Оценка движка не приводится к одной стороне (критично)

В `src/engine.ts` `score cp` берётся из UCI как есть. В UCI оценка считается **от стороны, которая
ходит**, поэтому две соседние позиции сравниваются в разных системах координат, а
`humanEvaluation()` ещё и берёт `Math.abs()` и теряет, кто вообще лучше стоит.

Пример поломки: момент ply 70 (правильный ход `Bf1`), ребёнок играет зевок `Rb8`, после которого
белые проигрывают −9.7. Приложение сейчас напишет «До хода: серьёзный перевес (3.1). После твоего
хода: перевес примерно как лишняя ладья (9.7)» — то есть похвалит за зевок.

Что сделать:
- ввести понятие цвета героя (`game.heroColor`, добавить поле в тип `Game` и в JSON);
- нормализовать оценку: если ходит не герой — умножить на −1, чтобы плюс всегда означал «герою лучше»;
- `humanEvaluation` не должна брать модуль: показывать словами и сторону, и величину
  («у тебя лучше примерно на ладью», «ты стоишь хуже на пешку», «примерно равно»);
- в обратной связи урока сравнивать нормализованные оценки и говорить прямо: стало лучше, хуже или
  так же, и на сколько.

## 2. Пересчитать все опровержения (критично)

Для каждого момента типа `find` в `src/content/games/kasparov-topalov-1999.json`:

- оставлять в `refutations` только ходы, которые теряют **не меньше 1.5 пешки** по сравнению с
  правильным. Сейчас там `Bg5` (−0.57), `d5` (−0.72), `Nc6+` (−0.65) — это «чуть хуже», а ребёнку
  говорят, что он ошибся. Такие убрать и заменить настоящими ошибками, найденными движком;
- поле `line` — реальный вариант из главного варианта движка длиной 2–4 хода, а не один заглушечный
  ход. Проверено: после `Nxc5` движок отвечает `dxc5` (конь просто висит, а в JSON написано `Kc8`);
  после `Qxf6` у чёрных `Qd1+` с матовой атакой (в JSON `Bb7`); после `Qa7` — `Nxd5` (в JSON `Bb7`);
- поле `why` переписать под то, что реально происходит в этом варианте. Сейчас про `Nxc5` написано
  «уводит коня от атаки», хотя настоящая причина — коня просто съедают. Формулировать простыми
  словами, как объясняют ребёнку, но по факту варианта;
- минимум два опровержения на момент сохраняется.

## 3. Проигрывать опровержение на доске

Сейчас опровержение только печатается текстом в панель комментария. Когда ребёнок сыграл
опровергнутый ход — показать на доске: его ход, затем ответы соперника по одному ходу с паузой
~700 мс, с подсветкой последнего хода и коротким текстом на каждом ходе. В конце — кнопка
«Вернуться и попробовать снова», которая откатывает позицию к моменту задания.

## 4. Заменить упражнения

Сейчас все 8 «упражнений» — те же 8 позиций из уже разобранной партии, FEN в FEN (ply 14, 34, 42,
46, 48, 54, 56, 70). Ребёнок вспомнит ход, а не идею. Плюс два из них без однозначного решения:
в первом движок первым ставит `Nd1` (`Bh6` второй, разрыв 1 сотая), во втором `Na5` вообще не входит
в тройку лучших.

Что сделать: собрать 8 новых позиций на те же темы — жертва качества за вскрытие линии, конь на d5,
охота на короля в центре, отвлечение защитника. Позиции брать **не из головы**: положи в
`src/content/sources/*.pgn` несколько классических партий целиком, а FEN упражнения получай
проигрыванием этого PGN до нужного полухода. Каждое упражнение обязано пройти пункт 0.4:
ход-ответ — первый выбор движка с отрывом ≥150 сотых, и позиция не из разбираемой партии.

## 5. Поддержка чёрных

`src/App.tsx`: `orientation: 'white'` захардкожен, в режиме игры стоит `chess.turn() !== 'w'` и текст
«Ты играешь белыми». Из-за этого любая партия, где герой играет чёрными, даёт перевёрнутую доску и
мёртвый экран игры — а смысл архитектуры был в «новая партия = один JSON без правок кода».

Заменить всё на `game.heroColor` из пункта 1: ориентация доски, чья очередь ходить в режиме игры,
тексты. Для проверки добавь вторую партию, где герой играет чёрными, и убедись, что оба режима
работают без изменений кода.

## 6. Подсветка и стрелки

- `lastMove` сейчас всегда `undefined`, поэтому при перемотке партии не видно, какой ход только что
  сделан. Передавать пару полей последнего хода;
- поля `arrows` и `highlight` есть в типах, но не рендерятся и ни разу не используются в JSON.
  Рисовать их через `drawable.autoShapes` chessground и проставить в комментариях к ключевым
  моментам: направление атаки, поле, за которое идёт борьба.

## 7. Мелочи

- В `src/engine.ts` нет таймаута и команды `stop`. Если поиск зависнет, очередь промисов встанет
  навсегда и движок умрёт до перезагрузки страницы. Добавить таймаут и отправку `stop`, с
  корректным отклонением промиса.
- Уровни «1200/1500/1800 Эло» на деле выставляют `Skill Level` 2/6/10, то есть подписи врут.
  Использовать `UCI_LimitStrength true` + `UCI_Elo`, `Skill Level` оставить как запасной путь.
- `registerStudyDay()` вызывается только при полном прохождении партии. Серия должна расти, если
  ребёнок решил хотя бы одно задание за день.
- Момент `ply: 72`: в JSON `Rd7+`, а в партии `Rd7` — это не шах, ладья d2 закрывает линию.
  Исправить и научить валидатор ловить неверный суффикс шаха/мата.
- Экран «Работа над ошибками» показывает только первую задачу по сроку: сразу после урока счётчик
  на главной обещает 3 задачи, а внутри «Возвращайся позже». Считать в счётчике только то, что
  реально доступно сейчас.

## 8. Усилить `scripts/validate-content.ts`

Добавить проверки, не требующие движка: `answerSan` равен настоящему ходу партии на этом `ply`;
суффикс шаха и мата соответствует позиции; FEN упражнения не встречается в PGN партии; `heroColor`
задан и совпадает со стороной, которая ходит в моментах типа `find`.

## Критерии приёмки

1. `npm run validate:content`, `npm run verify:engine` и `npm run build` проходят, все три стоят
   в CI перед деплоем.
2. `npm run verify:engine` печатает по каждому опровержению цену ошибки, и она везде ≥1.5 пешки.
3. Первый ход каждого `line` совпадает с ответом движка — скрипт это подтверждает.
4. Каждое упражнение: ответ — первый выбор движка с отрывом ≥150 сотых, FEN не из разбираемой партии.
5. В репозитории две партии: Каспаров — Топалов (герой белыми) и вторая, где герой чёрными. Обе
   полностью проходимы, доска повёрнута правильно, режим игры работает в обеих. Код при добавлении
   второй партии не менялся, кроме списка партий.
6. На зевке в режиме разбора приложение говорит, что стало хуже, и называет сторону — проверь
   вручную на позиции ply 70 ходом `Rb8`.
7. Опровержение проигрывается ходами на доске с возвратом к заданию.
8. Последний ход подсвечен при перемотке, стрелки видны минимум в пяти комментариях.
9. Сборка по-прежнему одна статика под GitHub Pages, `base: './'`, PWA и офлайн работают.

В конце напиши коротко: что поправил, какие опровержения и упражнения заменил и на что, и приложи
вывод `npm run verify:engine`.
