# Задание: интерактивный шахматный тренажёр по классическим партиям

Ты собираешь работающее веб-приложение с нуля. Пиши код, а не план. Ниже всё уже решено — не переспрашивай и не предлагай альтернативные стеки. Если что-то не указано, выбирай самый простой рабочий вариант и двигайся дальше.

## 1. Кто пользователь

Мальчик 10 лет, 1 юношеский разряд по шахматам. Русский язык — весь интерфейс и все тексты только по-русски. Занимается за одну сессию **не меньше часа**, так что урок должен быть содержательным: одной партии на 15 минут мало. Играет с iPhone, в портретной ориентации, пальцем.

Он уже умеет: читать нотацию, ставить мат в 2 хода, понимает «развитие», «центр», «размен». Он не понимает: «динамическая компенсация», «профилактика», «пешечная структура». Формулировки — как объясняет живой тренер ребёнку, без взрослого шахматного жаргона. Жаргон вводится только вместе с объяснением на месте.

## 2. Что делаем

PWA (устанавливается на домашний экран iPhone, работает офлайн) — тренажёр разбора классических партий. Не листалка ходов: ученик сам находит ходы на доске, ошибается, получает разбор своей ошибки, играет получившиеся позиции против движка.

Первая версия — **одна партия: Каспаров — Топалов, Вейк-ан-Зее 1999** (защита Пирца). Архитектура при этом должна быть такой, чтобы добавление следующих партий = добавление одного JSON-файла, без правок кода.

## 3. Стек — зафиксирован

- Vite + TypeScript + React. Без Next.js, без SSR, без бэкенда, без базы.
- Доска: **chessground** (та же, что на Lichess) — перетаскивание пальцем, стрелки, подсветка полей.
- Правила: **chess.js**.
- Движок: **stockfish** в браузере через WebWorker.
  - Важная ловушка: многопоточный Stockfish требует SharedArrayBuffer и заголовков COOP/COEP. GitHub Pages не позволяет их настроить, поэтому определяй `crossOriginIsolated`; при `false` грузи однопоточную сборку. Однопоточный вариант обязан работать — это основной сценарий на iPhone.
  - Все обращения к движку — через один модуль-обёртку с промис-API (`evaluate(fen, depth)`, `bestMove(fen, level)`), с очередью запросов. Никаких прямых `worker.postMessage` из компонентов.
- Прогресс: `localStorage` (позже, возможно, экспорт в JSON). Аккаунтов нет.
- Сборка — статика. Деплой: GitHub Pages либо локальный статический сервер. Vercel/Cloudflare не использовать.
- Зависимостей минимум. Никаких UI-китов, никаких стейт-менеджеров сверх встроенного React state/context.

## 4. Формат контента

Партия = один JSON-файл в `src/content/games/`. Код читает только этот формат:

```ts
type Game = {
  id: string;                 // "kasparov-topalov-1999"
  title: string;              // "Каспаров — Топалов, Вейк-ан-Зее 1999"
  opening: string;            // "Защита Пирца"
  result: string;             // "1-0"
  level: 1 | 2 | 3;           // сложность в программе
  intro: string;              // 3-5 предложений: кто играл, чем партия знаменита, на что смотреть
  pgn: string;                // главная линия, только ходы
  moments: Moment[];          // ключевые моменты по возрастанию ply
  drills: Drill[];            // упражнения после партии на ту же идею
};

type Moment = {
  ply: number;                // номер полухода в pgn, ПЕРЕД которым даётся задание (0-индекс)
  kind: "find" | "explain";   // find = ученик ищет ход на доске; explain = только комментарий
  prompt: string;             // вопрос ребёнку
  answerSan: string;          // правильный ход в SAN
  altAcceptable?: string[];   // ходы, которые тоже засчитываем как хорошие
  hints: string[];            // 2-3 подсказки по нарастающей: сначала идея, потом фигура, потом почти ответ
  explanation: string;        // почему этот ход, простым языком, 3-6 предложений
  refutations?: {             // почему НЕ работают напрашивающиеся ходы
    san: string;
    line: string;             // вариант-опровержение в SAN
    why: string;
  }[];
  arrows?: { from: string; to: string; color: "green" | "red" | "blue" }[];
  highlight?: string[];       // поля для подсветки, например ["d4","e7"]
};

type Drill = {
  fen: string;
  side: "w" | "b";
  prompt: string;
  answerSan: string;
  explanation: string;
};
```

## 5. Режимы работы (все четыре обязательны)

**А. Разбор.** Проход партии от начала до конца. Между ходами появляются моменты. Кнопки вперёд/назад/в начало, свайп по панели комментария или ленте ходов тоже листает. Свайп по доске не используется, чтобы не конфликтовать с перетаскиванием фигур пальцем. Внизу — лента ходов, по клику прыжок на позицию. Доска всегда развёрнута со стороны того, кто в этой партии главный герой (для Каспарова — белые).

**Б. Угадай ход.** На моменте `kind: "find"` доска блокирует листание, ученик должен сам сделать ход.
- верно → зелёная вспышка, `explanation`, плюс очки;
- неверно → красная вспышка, ход откатывается, показывается подсказка (первая из `hints`), вторая попытка;
- вторая ошибка → следующая подсказка, третья попытка;
- третья ошибка → показать правильный ход с объяснением, очки за момент = 0;
- если сыгранный ход есть в `refutations` — проиграть вариант-опровержение на доске автоматически по одному ходу с текстом «почему»;
- если ход не описан в `refutations` — спросить движок с лимитом времени 1-2 секунды и адаптивной глубиной и показать: оценка до / оценка после / лучший ответ соперника, с текстом «после твоего хода соперник играет … и ты теряешь …». Числа переводить в человеческий язык: «примерно как лишняя пешка», «как лишняя ладья».

**В. Доигрывание против движка.** С любой ключевой позиции — кнопка «сыграй сам». Ученик садится за сторону героя и доигрывает против Stockfish, ограниченного по силе (сначала `UCI_LimitStrength`, при отсутствии поддержки — `Skill Level` или выбор не первого хода из нескольких кандидатов; уровни: 1200 / 1500 / 1800 Эло). Оценка позиции по ходу игры показывается полоской. Кнопки «взять ход назад» и «сдаться / вернуться к разбору».

**Г. Задачник ошибок.** Все позиции, где ученик ошибся, копятся в `localStorage`. Отдельный экран «Работа над ошибками» подсовывает их снова: сначала через день, потом через три, потом через неделю (простой интервальный повтор, срок хранится вместе с позицией). Задача уходит из задачника после двух подряд верных решений.

## 6. Экраны

1. **Главная** — список партий карточками (пройдено / в процессе / закрыто), полоска прогресса, счётчик дней подряд, кнопка «Работа над ошибками» с числом накопленных задач.
2. **Партия** — вступление (`intro`) и кнопка «Начать».
3. **Доска** — основной экран, режимы А-В.
4. **Итог партии** — сколько ходов угадано из скольких, время, список ошибок с возможностью повторить, кнопка к упражнениям `drills`.
5. **Работа над ошибками**.

Требования к UI: mobile-first, вертикаль, доска шириной во весь экран, кнопки не меньше 44px, текст комментария под доской в прокручиваемой панели, шрифт крупный. Тёмная и светлая тема по системной настройке. Никаких мелких иконок без подписей. Анимация хода — быстрая (150-200 мс), без украшательств.

## 7. Геймификация — сдержанно

Очки за угаданный ход: 3 без подсказок, 2 с одной подсказкой, 1 с двумя, 0 при показе ответа. Счётчик дней подряд. Партия считается пройденной при 70% очков от максимума. Никаких таймеров обратного отсчёта, никаких «жизней» и звуковых фанфар — от этого ребёнок нервничает и бросает.

## 8. Контент первой партии

PGN ниже проверен на легальность (87 полуходов, python-chess). Используй его как есть, не «исправляй» по памяти:

```
1.e4 d6 2.d4 Nf6 3.Nc3 g6 4.Be3 Bg7 5.Qd2 c6 6.f3 b5 7.Nge2 Nbd7 8.Bh6 Bxh6
9.Qxh6 Bb7 10.a3 e5 11.O-O-O Qe7 12.Kb1 a6 13.Nc1 O-O-O 14.Nb3 exd4 15.Rxd4 c5
16.Rd1 Nb6 17.g3 Kb8 18.Na5 Ba8 19.Bh3 d5 20.Qf4+ Ka7 21.Rhe1 d4 22.Nd5 Nbxd5
23.exd5 Qd6 24.Rxd4 cxd4 25.Re7+ Kb6 26.Qxd4+ Kxa5 27.b4+ Ka4 28.Qc3 Qxd5
29.Ra7 Bb7 30.Rxb7 Qc4 31.Qxf6 Kxa3 32.Qxa6+ Kxb4 33.c3+ Kxc3 34.Qa1+ Kd2
35.Qb2+ Kd1 36.Bf1 Rd2 37.Rd7 Rxd7 38.Bxc4 bxc4 39.Qxh8 Rd3 40.Qa8 c3
41.Qa4+ Ke1 42.f4 f5 43.Kc1 Rd2 44.Qa7 1-0
```

Ключевые моменты, которые нужно расписать (это скелет, тексты пишешь сам, языком 10-летнего). Тип `find` — там, где ученик ищет ход:

1. **6.f3** — explain. Белые не развивают фигуру, а строят стену для пешечной атаки. Куда пойдёт король белых и почему.
2. **8.Bh6** — find. Размен слонов: снести главного защитника чёрного короля. Спросить: как разменять лучшего защитника соперника.
3. **11.O-O-O** — explain. Рокировки в разные стороны = гонка: кто первым доберётся до чужого короля. Отсюда весь дальнейший счёт.
4. **18.Na5** — find. Конь лезет в самое неприятное место, атакует слона b7 и держит поля вокруг короля.
5. **19.Bh3** — explain. Слон из угла смотрит через всю доску на поле e6/d7 — важно для будущего Re7.
6. **22.Nd5** — find. Удар в центре, вскрывающий линии; заодно уводит защитника.
7. **24.Rxd4!!** — find, **главный момент партии**. Отдаётся целая ладья. Даём три подсказки и очень подробное объяснение: за ладью белые вскрывают короля и загоняют его пешком через всю доску. Обязательно показать, что случится при «нормальном» 24.Qe3 или 24.Nc3 — движком.
8. **25.Re7+** — find. Продолжение той же идеи, короля гонят.
9. **28.Qc3!** — find. Тихий ход без шаха посреди атаки — самый трудный для понимания. Объяснить, что шах ради шаха не всегда лучший, важнее угроза мата.
10. **29.Ra7!** — find. Подключение второй ладьи, у чёрного короля кончаются поля.
11. **36.Bf1!** — find. Ещё один тихий ход: слон отрезает короля.
12. **37.Rd7** — explain. Размен, после которого всё кончено.
13. **44.Qa7** — explain. Почему Топалов сдался: показать мат в вариантах.

Для каждого `find` обязательно: 2-3 подсказки по нарастающей, объяснение, и минимум 2 записанных `refutations` на самые естественные детские ходы (шах ради шаха, взятие ради взятия). Опровержения проверь движком, а сами варианты — на легальность через chess.js. **Ни один SAN в JSON не должен быть нелегальным** — добавь скрипт `npm run validate:content`, который прогоняет все партии, моменты, альтернативы, опровержения и drills через chess.js и падает с понятной ошибкой.

`drills`: 6-8 позиций после партии на те же идеи — размен защитника короля, вскрытие линии жертвой, тихий ход в атаке, загон короля. Можно брать из других классических партий, но каждую позицию проверить движком, что решение действительно единственное или явно сильнейшее.

## 9. Офлайн и PWA

Manifest, иконки, service worker (Workbox или руками). После первого открытия всё работает без сети: доска, движок wasm, контент, прогресс. Проверить, что установка на домашний экран iPhone работает и приложение открывается в standalone-режиме без адресной строки.

## 10. Критерии приёмки

Считаем готовым, когда всё перечисленное выполняется:

1. `npm run build` проходит без ошибок и предупреждений TypeScript.
2. `npm run validate:content` зелёный: все SAN легальны, все FEN валидны, ply-индексы в пределах партии.
3. Партия Каспаров — Топалов проходится целиком в режиме «Угадай ход»: 13 моментов, включая 8 заданий `find`; для заданий работают подсказки, откат неверного хода и показ опровержений.
4. Ошибочный ход, не описанный в JSON, всё равно получает разбор от движка за разумное время (до ~3 секунд на телефоне) — значит, глубину подбираешь под реальность, а не 25.
5. Доигрывание против движка работает с трёх разных позиций, движок ходит легально и не зависает.
6. Задачник ошибок наполняется, интервалы считаются, задача уходит после двух верных решений.
7. Прогресс переживает перезагрузку страницы и закрытие приложения.
8. В офлайн-режиме (авиарежим) приложение открывается и полностью работает.
9. На экране iPhone (375px ширины) ничего не обрезается и не требует горизонтальной прокрутки.
10. В README: как запустить локально, как собрать, как добавить новую партию (пошагово, на примере).

## 11. Чего не делать

- Не делать регистрацию, аккаунты, облако, серверную часть.
- Не подключать внешние API во время урока (приложение обязано работать офлайн).
- Не делать редактор партий и админку — контент правится руками в JSON.
- Не тащить UI-библиотеки и не изобретать свой рендер доски.
- Не писать комментарии взрослым шахматным языком.
- Не добавлять партии сверх первой, пока первая не проходится целиком.
